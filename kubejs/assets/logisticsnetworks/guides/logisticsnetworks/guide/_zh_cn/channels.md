# 通道

每个节点有 9 个通道，索引从 0 到 8。

传输路径的构建方式如下：

1. 源节点通道处于发送端模式
2. 目标节点通道具有相同的通道索引
3. 目标通道处于接收端模式
4. 两个通道上的资源类型相同

因此，通道索引和资源类型必须匹配。

代码中的资源类型：

1. 物品
2. 流体
3. 能量
4. 化学品
5. 魔源

化学品类型仅在加载 Mekanism 且该节点拥有 Mekanism 化学品升级时可选。

魔源类型仅在加载 Ars Nouveau 且该节点拥有 Ars 魔源升级时可选。

## 红石规则

发送端通道直接使用红石模式：

1. 始终开启：无需红石信号即可运行。
2. 始终关闭：永不运行。
3. 高信号：仅当红石信号大于 0 时运行。
4. 低信号：仅当红石信号为 0 时运行。

接收端通道仅在红石模式为“始终开启”时被缓存。

## 分配模式

分配模式应用于发送端通道：

1. 优先级：优先尝试优先级值较高的目标。
2. 最近优先：优先尝试最近的目标节点。
3. 最远优先：优先尝试最远的目标节点。
4. 循环：成功传输后轮换目标。
5. 配方循环：按配方比例循环轮换。

循环和配方循环在成功移动后轮换目标。配方循环按比例分配物品，以匹配各目标的配方比例。

## 过滤模式

每个通道都有过滤模式：

1. 任意：匹配一个白名单过滤器即可。
2. 全部：必须匹配所有白名单过滤器。

这控制白名单检查。黑名单匹配始终阻止。

当前传输代码检查物品、流体和化学品通道的过滤器。
能量和魔源通道不读取过滤器槽位进行匹配。

## 通道命名

每个通道可以被赋予自定义名称。这仅是一个标签，不影响传输逻辑。
